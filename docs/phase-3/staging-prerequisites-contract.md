# Platform prerequisites before FirstWriter

Staging FirstWriter now requires a reviewed platform bundle and a successful foundation readback before APP writes. K8S owns creation of the Service, TargetGroupBinding, two base NetworkPolicies, SecretProviderClass, migration ServiceAccount/egress NetworkPolicy and runtime public ConfigMap. APP only reads its existing authorized Service/SPC/SA/ConfigMap resources; it neither gains NP/TGB permissions nor creates the public ConfigMap in this path.

Add these public fields to the existing immutable `platform.json`: `StagingPrerequisitesJson`, `StagingPrerequisitesSha256`, `PlatformPrerequisitesReceiptJson`, `PlatformPrerequisitesReceiptSha256`, `PlatformPrerequisitesReceiptBucket`, `PlatformPrerequisitesReceiptKey`, and `PlatformPrerequisitesReceiptVersionId`. JSON fields preserve exact UTF-8 text; hashes bind those bytes. Receipt key is `foundation-addons/manifests/staging/<appSourceCommit>/readback.json`, with an explicit immutable VersionId. The bundle itself includes the exact staging Terraform output JSON, bucket/key/VersionId/hash and `target_group_arn` plus APP/K8S commit bindings.

The existing platform artifact bucket/key/VersionId/SHA256 and release `platformInputsSha256` transport and bind these additions. No eighth APP artifact is added; existing six/seven-input receipt field names and hashes keep their historical meanings. Old receipts remain historical evidence, but new FirstWriter execution fails closed if the platform additions are absent. The separately versioned public ConfigMap remains the seventh artifact and must match the bundle's public hash.

The launcher and offline packager validate bundle/receipt hashes, exact eight-object set, staging/source/account/target ARN and migration/public hash bindings. Only `CREATED_VERIFIED` or `EXISTING_VERIFIED` foundation receipts pass, with matching object metadata/spec/data and UID/resourceVersion. `deploy-app.ps1` then performs permitted live reads under the existing shared lock before workload creation or migration. Missing, malformed, partial or drifted readback stops the rollout; no Secret GET/list occurs. APP continues to create its own zero-writer Deployment/runtime SA and restore HPA only after migration, as before.

K8S's explicit-gated private foundation override performs create-only provisioning. It requires all eight absent or all eight matching, server dry-run, an absence recheck, and exact post-create readback. Any partial creation requires separately reviewed recovery. APP cannot live-read TGB/NetworkPolicies; require a fresh reviewed private foundation readback immediately before activation to address that ownership boundary. A versioned receipt does not prove resources stayed unchanged after capture.

Explicit external inputs remain required: real staging Terraform outputs, immutable object versions, migration IRSA/secret/KMS metadata, DB/ALB/AWS network inputs, and an authorized cloud window. No values are invented. R4 NOT_RUN/NOT_CAPTURED and submission NOT_READY remain unchanged; no route, target-health, CSI, migration, rollout, or production success is claimed.

Checks: `tests/app-prerequisites-contract.ps1`, `tests/staging-first-deployment-contract.ps1`, and full `tests/pipeline-contract.ps1`. The artifact/readback helper `scripts/staging-prerequisites-contract.ps1` must remain identical to its K8S counterpart.
