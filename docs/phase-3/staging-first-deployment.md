# Reviewed staging first deployment

`scripts/deploy-app.ps1` accepts an optional `-StagingWorkloadFile` adapter for staging `FirstWriter` releases. Without `-ExecuteReviewedPlan` it only validates and renders files; there are no AWS or Kubernetes calls. The separate `scripts/deploy.ps1` executor is staging-only and requires the explicit `-ApplyReviewedPlan` switch plus the reviewed staging Terraform root; production initialization is rejected. The launcher performs the cloud-window check before the CodeBuild handoff.

## Reviewed inputs

Supply the existing release JSON, its expected SHA256, and the platform JSON bound by `platformInputsSha256`. Add `stagingWorkloadSha256` to the reviewed release, pointing to the SHA256 of a JSON Kubernetes `v1/List` containing exactly the rendered platform Deployment, ServiceAccount and HorizontalPodAutoscaler. Each must be named `oficina-app` in `oficina-staging`. Obtain this bundle from the reviewed K8S renderer output, retaining its probes, resource requests, runtime public configuration, Secret references, CSI volumes and security settings. Do not use the APP local-Kind manifests or strip the platform pod configuration.

The adapter checks the bundle digest, APP image, selector/labels, IRSA reference, disabled application Flyway, Hibernate validation and staging HPA capacity. The full bundle remains a review input: structural validation is not a replacement for reviewing every pod setting. It does not generate, retrieve, or print secret values. The output directory contains reviewed manifests and must have appropriate executor access restrictions.

The release must also contain scalar `artifactSha256` and `deployerImageDigest`. Provide `-SourceArchiveFile` matching the source hash, `-SourceKey releases/app/staging/bundle.zip`, and the executor's independently reviewed `-ExpectedDeployerImageDigest`. These checks bind local inputs; they do not attest the running executor image, inspect archive extraction, or prove ECR existence. The existing launcher/executor verification remains required before integrating this adapter. No source, digest, or activation check was removed from those entry points.

Execution additionally requires `-StateBucket` for the existing shared deployment lock and `-CloudWindowEvidenceFile` accepted by the existing staging cloud-window guard. The adapter acquires the conditional shared lock before cluster reads and holds it through initialization, migration, rollout and HPA restoration. It rechecks the window before each Kubernetes write and conditionally releases its own lock in `finally`. A closed window or failed lock acquisition prevents cluster access.

## Fresh and existing workloads

If all three resources are absent, a successful `kubectl get --ignore-not-found=true` is required for each. Forbidden, network, malformed JSON and other errors are failures, never evidence of absence. For a fresh release, set `previousImage` equal to the target `image` to explicitly record that there is no previous application workload. Existing APP-labelled pods forbid initialization.

The adapter creates the service account and Deployment with `kubectl create`, so an existing resource or concurrent creation cannot be overwritten. The Deployment preserves the reviewed pod configuration but starts with zero replicas and `Recreate`. The HPA remains absent during migration; creating an autoscaler before the migration is unnecessary. After readback validation and the existing zero-writer drain check, the adapter runs the existing migration Job and verifies completion for the reviewed migration image, applies the rollout patch, waits for rollout, then restores the HPA (minimum 1, maximum 2, CPU target 60%).

If all resources already exist, the adapter validates their current image, service account/IRSA, selector and HPA contract, then follows the existing FirstWriter drain path. It does not replace existing resources with the bootstrap bundle. If only some resources exist, it fails before writes. An interrupted bootstrap or failed migration may intentionally leave zero replicas, a service account, or no HPA: inspect and review recovery before retrying. There is no automatic deletion, rollback, migration retry or partial-resource repair.

## External blockers before execution

1. **K8S-owned RBAC:** the currently inspected `k8s/platform/base/deployer-rbac.yaml` lacks service-account and Job permissions. Review staging-scoped permissions for APP service-account `get/create` and migration Job `get/watch/create`, plus any migration-identity provisioning owned by K8S. Kubernetes RBAC cannot constrain `create` by `resourceNames`; use namespace scoping and reviewed admission constraints where needed. This APP change does not grant RBAC, create rolebindings, or broaden production access.
2. **Platform prerequisites:** the staging namespace, APP Service/routing, CSI SecretProviderClass and driver, public ConfigMap (including RDS CA/customer public keys), migration service account/Secret, runtime Secret references, policies and DB access must already exist. The three-object bundle does not install platform infrastructure or provision credentials.
3. **Release evidence:** provide the reviewed full workload bundle/hash, APP and migration image digests, selected deployer digest verified in ECR, source archive/release/platform bindings, staging IRSA role, New Relic metadata, approved cloud window and lock bucket. Existing platform/deployer provenance and live source-prefix issues must be resolved separately.
4. **Activation integration:** implement and review the executor integration separately, preserving trusted archive extraction, actual executor image verification, existing source-prefix/deployer guards, staging-only authorization and success/promotion evidence. The disabled executor and existing production paths remain unchanged.

Run `pwsh -NoProfile -File tests/staging-first-deployment-contract.ps1` for mocked fresh/existing/error cases and `pwsh -NoProfile -File tests/pipeline-contract.ps1` for the complete PowerShell contract gate. The tests do not contact AWS or a cluster and establish no runtime deployment evidence.
