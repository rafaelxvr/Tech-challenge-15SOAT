# Migration identity prerequisite

The staging FirstWriter adapter requires three public platform fields: `MigrationIdentityJson` (exact K8S Terraform output string), `MigrationIdentitySha256` (SHA256 of its UTF-8 bytes), and `MigrationNetworkPolicySha256` (K8S renderer receipt's policy hash). The existing `platformInputsSha256` and immutable platform S3 object key/VersionId bind this envelope; no new unversioned download or secret value is introduced.

The identity schema binds the APP source commit, staging namespace, `oficina-migration-staging` ServiceAccount, distinct role `oficina-phase3-staging-migration`, foundation OIDC issuer/provider, exact bootstrap-review hash, and five secret ARN/VersionId references. Each reference also requires nonsecret metadata receipt SHA256 and explicit AWS/CUSTOMER KMS ownership; customer keys must be exact same-account key ARNs. These are required reviewed inputs, not generated live ARN claims. K8S owns the optional/default-disabled role, SA, and migration egress policy; the APP runtime `oficina-app` role remains unchanged.

`offline-release-handoff.ps1` validates the identity before packaging and preserves the exact bootstrap review serialization. Launcher/executor input validation rejects missing, altered, or production identities before external calls. `deploy-app.ps1` validates the live SA role annotation and disabled automatic API token mount under the shared deployment lock before any cluster writes, then reads it again immediately before bootstrap. A missing/malformed/mismatched SA stops migration. The existing Job explicitly selects that SA and the `oficina-migration` label used by the K8S egress policy. APP never creates the migration SA or IAM role.

For handoff, retain the K8S `migration-render-receipt.json`, exact identity and NetworkPolicy bytes, and nonsecret Secrets Manager/KMS review receipts. Hashes bind reviewed artifacts; they do not prove live network policy or cloud metadata. The policy must explicitly permit DNS, all reviewed RDS subnets on TCP5432, and the reviewed STS/Secrets Manager HTTPS path on TCP443. EKS IRSA webhook projection, DB connectivity, migration/bootstrap completion, and rollout remain unverified until a separately authorized staging run records them.

Production behavior remains gated by its existing independent contract; this staging identity path does not enable production. Cloud R4 rows remain NOT_RUN/NOT_CAPTURED and submission remains NOT_READY. Known public ConfigMap/SPC/Service/base NetworkPolicies and TargetGroupBinding are separate platform prerequisites.

Offline checks: `tests/migration-identity-contract.ps1` covers scalar/type/hash/source/secret/KMS rejection; `tests/staging-first-deployment-contract.ps1` covers locked SA checks and actual Job wiring using mocked boundaries; `tests/pipeline-contract.ps1` runs the existing launcher/executor/rollout contracts. Fixture account IDs, ARNs, and metadata hashes are synthetic and are not activation inputs.
